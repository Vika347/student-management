# Student Management

Лабораторная работа №3 по веб-программированию.

В рамках лабораторной работы была разработана серверная часть приложения для управления данными студентов. Информация хранится в PostgreSQL, а взаимодействие с приложением осуществляется через REST API.

В приложении реализованы операции со студентами, регистрация и авторизация пользователей, а также разграничение доступа на основе ролей.

## Технологии

В проекте используются:

- Java 17
- Jakarta EE 10
- Payara Server 6
- PostgreSQL
- JPA (EclipseLink)
- Maven
- OpenAPI
- JWT (access- и refresh-токены)
- BCrypt
- Jakarta Bean Validation

## Структура проекта

Для работы со студентами используются следующие классы:

- `Student` — JPA-сущность, соответствующая таблице студентов в базе данных.
- `StudentDTO` — объект для передачи данных между клиентом и сервером.
- `StudentMapper` — преобразует сущности в DTO и обратно.
- `StudentRepository` — отвечает за взаимодействие с базой данных.
- `StudentService` — содержит бизнес-логику работы со студентами.
- `StudentResource` — обрабатывает HTTP-запросы к REST API.

Авторизация реализована отдельно с использованием сервисов пользователей, JWT и фильтров безопасности.

В приложении разделены уровни обработки HTTP-запросов, бизнес-логики и доступа к данным.

## Работа со студентами

Приложение позволяет создавать, получать, изменять и удалять записи студентов.

### REST API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/students` | Получить список студентов |
| GET | `/api/students/{id}` | Получить студента по ID |
| POST | `/api/students` | Создать студента |
| PUT | `/api/students/{id}` | Полностью обновить данные студента |
| PATCH | `/api/students/{id}` | Частично изменить данные студента |
| DELETE | `/api/students/{id}` | Удалить студента |

Дополнительно реализованы:

- Поиск студентов по ФИО.
- Фильтрация по группе и общежитию.
- Сортировка результатов.
- Пагинация.
- Проверка корректности входных данных.
- Проверка уникальности номера ИСУ.

При некорректных запросах сервер возвращает соответствующие HTTP-коды и сообщения об ошибках.

## Авторизация и безопасность

Для авторизации пользователей используются JWT-токены.

Пользователь может зарегистрироваться, войти в приложение и обновить access-токен с помощью refresh-токена.

Пароли пользователей хранятся в базе данных в виде BCrypt-хешей.

### Эндпоинты авторизации

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/auth/register` | Регистрация пользователя |
| POST | `/api/auth/login` | Авторизация пользователя |
| POST | `/api/auth/refresh` | Обновление access-токена |

После успешной авторизации сервер возвращает два токена:

- **Access-токен** — действует 15 минут и используется для доступа к защищённым ресурсам.
- **Refresh-токен** — действует 7 дней и позволяет получать новый access-токен.

Для обращения к защищённым эндпоинтам необходимо передавать access-токен в HTTP-заголовке:

```http
Authorization: Bearer <access_token>
```

### Роли пользователей

В приложении реализованы две роли:

- **USER** — может просматривать список студентов и информацию об отдельном студенте.
- **ADMIN** — может просматривать, создавать, изменять и удалять студентов.

Проверка JWT осуществляется в `JwtFilter`, а проверка прав доступа — в `RoleFilter`.

При отсутствии или недействительности токена сервер возвращает HTTP `401 Unauthorized`.

Если пользователь не обладает необходимыми правами, возвращается HTTP `403 Forbidden`.

## База данных

Для хранения информации используется PostgreSQL.

В базе данных хранятся сведения о студентах и зарегистрированных пользователях.

Работа с базой данных осуществляется через JPA с использованием EclipseLink.

Для подключения приложения к PostgreSQL на сервере Payara используется:

- JDBC Connection Pool: `StudentPool`
- JDBC Resource: `jdbc/StudentDB`

## Запуск приложения

### Требования

Для запуска необходимы:

- JDK 17
- Maven
- PostgreSQL
- Payara Server 6

### 1. Настройка PostgreSQL и Payara

Необходимо создать базу данных PostgreSQL, доступную приложению, и настроить подключение к ней через Payara.

Для этого создаётся JDBC Connection Pool `StudentPool` с параметрами подключения к PostgreSQL.

Затем создаётся JDBC Resource с JNDI-именем `jdbc/StudentDB`, который использует созданный пул соединений.

Пример параметров окружения находится в файле `.env.example`.

Этот файл служит образцом конфигурации. Приложение не считывает его автоматически: параметры подключения к базе данных задаются в Payara.

### 2. Настройка JWT

Для подписи JWT-токенов используется переменная окружения `JWT_SECRET`.

На macOS или Linux можно сгенерировать случайный секрет следующей командой:

```bash
export JWT_SECRET="$(openssl rand -hex 32)"
```

Переменная окружения должна быть доступна процессу Payara при запуске сервера.

Настоящие пароли, секретные ключи и токены не должны сохраняться в Git-репозитории.

### 3. Сборка проекта

Из корневой директории проекта выполнить:

```bash
mvn clean package
```

В результате сборки создаётся WAR-файл:

`target/student-management.war`

### 4. Развёртывание приложения

Запустить Payara Server с настроенным окружением.

Затем выполнить:

```bash
asadmin deploy --force=true target/student-management.war
```

После успешного развёртывания базовый адрес REST API:

http://localhost:8080/student-management/api

## Тестирование через Postman

Для тестирования подготовлена коллекция:

`student-management-postman.json`

Коллекция содержит три группы запросов:

1. **Авторизация** — регистрация, вход пользователей, обновление токена и проверка ошибок.
2. **Работа со студентами (USER)** — получение данных, поиск и проверка доступа.
3. **Работа со студентами (ADMIN)** — создание, изменение и удаление студентов.

Для использования коллекции необходимо:

1. Запустить приложение на Payara.
2. Импортировать `student-management-postman.json` в Postman.
3. Проверить значение переменной `baseUrl`.
4. Заполнить переменные с учётными данными тестовых пользователей.
5. Выполнить запрос авторизации для получения JWT.
6. Отправлять запросы из соответствующих разделов коллекции.

Пароли и токены в экспортированной коллекции не сохраняются.

## Обработка ошибок

В приложении предусмотрена обработка ошибок, возникающих при работе REST API.

В частности, обрабатываются:

- Ошибки валидации входных данных — `400 Bad Request`.
- Отсутствие или недействительность авторизации — `401 Unauthorized`.
- Недостаток прав доступа — `403 Forbidden`.
- Отсутствие запрашиваемой записи — `404 Not Found`.
- Конфликт данных, например при повторной регистрации пользователя, — `409 Conflict`.

Ошибки возвращаются клиенту в структурированном JSON-формате.

## Запуск через Docker

Приложение можно запустить с помощью Docker Compose. В этом случае Java backend на Payara и PostgreSQL работают в отдельных контейнерах.


Отдельно устанавливать Java, Maven, Payara и PostgreSQL не требуется.

### 1. Клонирование проекта

```bash
git clone https://github.com/Vika347/student-management.git
cd student-management
```

### 2. Настройка переменных окружения

Создать файл `.env` на основе примера:

```bash
cp .env.example .env
```

Открыть `.env` и задать собственные значения:

- `POSTGRES_PASSWORD` — пароль пользователя PostgreSQL.
- `JWT_SECRET` — случайный секрет для подписи JWT длиной не менее 32 байт.

Настоящие пароли и секреты не должны добавляться в Git.

### 3. Сборка и запуск

```bash
docker compose up --build -d
```

Docker Compose запускает два сервиса:

- `postgres` — PostgreSQL 17.
- `payara` — Java-приложение на Payara Server 6.

При первой инициализации пустой базы выполняется скрипт `docker/init.sql`, создающий таблицы `students` и `users`.

### 4. Адреса приложения

После успешного запуска REST API доступно по адресу:

`http://localhost:8081/student-management/api`

OpenAPI-спецификация доступна по адресу:

`http://localhost:8081/openapi`

Для тестирования можно использовать коллекцию `student-management-postman.json`, изменив переменную `baseUrl` на адрес Docker API.


### 5. Остановка приложения

```bash
docker compose down
```

Эта команда останавливает и удаляет контейнеры, но сохраняет данные PostgreSQL в Docker volume.

Для повторного запуска:

```bash
docker compose up -d
```

Не используйте `docker compose down -v`, если необходимо сохранить данные базы: флаг `-v` удаляет также Docker volumes.
